The picture in your head

An AWS account is a sealed box. Everything you build (servers, databases, buckets) lives inside one box, and the bill is counted per box. Your organization is a few boxes grouped together.

Organization └─ Root top folder, not a person. Rules here hit every account ├─ Management created the org, pays all bills. Keep it empty ├─ Identity delegated admin for IAM Identity Center: your logins live here └─ Portfolio where your apps run. The movie app goes here

Four kinds of "who"

IdentityWhat it isWhen you use it
Root userThe email + password of one account. Can do anything, can't be limited.Almost never. Billing, emergencies.
IAM userA login that lives inside one account, often with a permanent access key.Avoid. A leaked key = someone else's servers on your bill. (tf-learning was one.)
Identity Center userYour person, created once in the identity account. Can open any account you assign.Every day. Console and CLI.
IAM roleA set of permissions anyone allowed can "put on" for a while. Keys expire by themselves.Used under the hood: by your SSO login, by GitHub Actions, by the running app.

Where your code meets AWS

AWS doesn't "import" a GitHub repo. Two separate things happen:

  1. Terraform builds the empty house (network, database, servers, CDN) in the portfolio account. You run it from your laptop.
  2. GitHub Actions moves the furniture in. On every push to main it builds the API image and the website and ships them into that house, using a role (no keys stored in GitHub).
1

Lock the doors

Sign in: management account, as root
  1. Go to https://signin.aws.amazon.com → Root user → your main email.
  2. Top right, your name → Security credentials → Assign MFA device. Use an authenticator app (or a passkey).
  3. On the same page, under Access keys: there should be none. If there are, delete them.
  4. Billing and Cost Management → Billing preferences → turn on Free Tier usage alerts and CloudWatch billing alerts.
  5. Optional but good: do steps 1–3 for the root user of the identity and portfolio accounts too. They have no password yet: use Forgot password on the root sign-in page with that account's email.
WhyThe root user can close accounts and change billing. MFA means a stolen password alone isn't enough.
2

Create your daily login

Sign in: identity account (from management: your name → Switch role)

To reach the identity account: in the management account, open AWS Organizations and copy the identity account's 12-digit ID. Then click your name → Switch role → that ID → role OrganizationAccountAccessRole.

  1. Open IAM Identity Center. If it says it's managed elsewhere, do these steps from the management account instead.
  2. Users → Add user: your username, your email. Open the invite email, set a password, register MFA.
  3. Permission sets → Create permission set → Predefined → AdministratorAccess. Set session duration to 8 hours.
  4. AWS accounts → tick Portfolio → Assign users or groups → your user → AdministratorAccess → Submit.
  5. Dashboard → copy the AWS access portal URL (https://d-xxxxxxxxxx.awsapps.com/start). Bookmark it.
How you'll sign in from now onOpen the portal URL → log in → click Portfolio → AdministratorAccess → Management console. No more root, no more switch role.
3

Connect your laptop

Terminal on your Mac
  1. Set up the profile once. Answers: session name me, start URL = your portal URL, region ap-southeast-7, pick Portfolio + AdministratorAccess, profile name portfolio. 
    aws configure sso
  2. Each working day (opens the browser to confirm): 
    aws sso login --profile portfolio
  3. Make it the default for this terminal tab: 
    export AWS_PROFILE=portfolio
  4. Check who you are: 
    aws sts get-caller-identity
    You should see the portfolio account number and an assumed-role/AWSReservedSSO_AdministratorAccess… ARN.
  5. Remove the old key from your Mac: open ~/.aws/credentials and delete the [default] block. Then, in whichever account tf-learning lives, IAM → Users → tf-learning → delete it.
4

Prepare the portfolio account

Sign in: portfolio account via the portal

Settings like regions and budgets belong to each account separately. What you did in the old account doesn't carry over.

  1. Enable Bangkok. Your name → Account → AWS Regions → Asia Pacific (Thailand) → Enable. Wait until it says Enabled.
  2. Budget. Billing and Cost Management → Budgets → Cost budget, monthly USD 50, email at 50 / 80 / 100 % actual and 100 % forecast. (If the console says only the management account can see billing, create it there and filter by the portfolio account.)
  3. Block public S3. S3 → Block Public Access settings for this account → all four on.
  4. Check the region has what we need (read-only): 
    bash infra/scripts/check-region.sh
5

Point Terraform at the portfolio account

Terminal, repo folder infra/envs/demo

Terraform state is Terraform's notebook: a file listing everything it created. It lives in an S3 bucket so it isn't lost with your laptop. The old account used state-bucket-portfolio-project; the portfolio account has state-bucket-rungroj-portfolio-project, so versions.tf must name that one.

  1. See whether that bucket is in the portfolio account: 
    aws s3 ls | grep state-bucket
    It should list state-bucket-rungroj-portfolio-project. Put that name in the backend "s3" block of versions.tf.
  2. Connect Terraform to it (safe, creates nothing): 
    terraform init -reconfigure
  3. Preview. The output must show the portfolio account ID: 
    terraform plan
Read every planLook at the last line: Plan: X to add, Y to change, Z to destroy. If Z is not 0 and you didn't expect it, stop and ask.

Build the AWS side, one phase at a time

Claude writes one file → you read it → you run plan + apply

Each phase is one small step. Claude explains each file in plain words. You run:

terraform plan
terraform apply
PhaseWhat it buildsMonthly cost
2 NetworkPrivate network (VPC), subnets, internet gateway, security groups (who may talk to whom)~0
3 DatabasePostgreSQL on RDS, no internet access, passwords in SSM Parameter Store~USD 15
4 ContainersECR (image storage), ECS Fargate (runs the API), internal load balancer~USD 25
5 EdgeS3 for the website, CloudFront (the public URL), WAF (blocks attacks)~USD 9
Why this orderEach layer needs the one before it: the database sits in the network, the API needs the database, the public URL needs the API.
7

Put the code on GitHub and let it deploy

github.com + terminal
  1. The repo already exists: Imperator7/Movie-ticketing. It is public today; decide whether to make it private (Settings → General → Danger zone).
  2. Before pushing, make sure no secrets go up. .env files must be git-ignored: 
    git check-ignore .env apps/api/.env
    Both paths should print back. If one doesn't, stop and ask.
  3. Push your work: 
    git push origin main
  4. Watch the Actions tab. The existing CI must turn green before anything deploys.
  5. Phase 6 (Claude writes it): a GitHub OIDC provider (the portfolio account has none yet) and an OIDC role in the portfolio account. GitHub proves "I am this repo, on main" and AWS gives it short keys. No AWS key is ever pasted into GitHub.
  6. On GitHub: Settings → Branches → protect main (require CI to pass). Settings → Environments → demo → require your approval before deploys.
Neverpaste an AWS access key into GitHub Secrets. If a guide tells you to, it's the old way.
8

Go live

Stripe dashboard + portfolio console
  1. Stripe → turn on Test mode → Developers → API keys. Put the secret key into SSM Parameter Store as a SecureString (Claude gives you the exact name). Never in a file, never in chat.
  2. Stripe → Webhooks → add https://YOUR-ID.cloudfront.net/api/v1/payments/webhook, then store its signing secret the same way.
  3. Walk the app on the public URL: register, pick seats, pay with test card 4242 4242 4242 4242, see the ticket.

Safety rules to keep forever

  • No permanent AWS keys anywhere. SSO on the laptop, OIDC in GitHub, roles inside AWS.
  • Root only for billing and emergencies, always with MFA.
  • Nothing runs in the management account. Apps go in portfolio.
  • Read the plan before apply. Unexpected "destroy" = stop.
  • Secrets live in SSM Parameter Store. Never in git, chat, screenshots or GitHub Secrets as AWS keys.
  • Repo stays private. Branch protection on main.
  • Budget alarm on. A surprise email beats a surprise bill.
